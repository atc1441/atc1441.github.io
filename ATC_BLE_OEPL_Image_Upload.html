NFC

What a phone meets when it is held against the tag: the message it reads without any app, and the command channel an app uses to talk to the tag the way this page does over BLE.

chip – commands –
The message a tap reads
Written to flash and kept across reboots. Clearing puts the tag's own default message back rather than leaving a phone with nothing to read.
Command channel
The same switch as under Protection, where it sits with the PIN – both decide who may command this tag, so changing one without seeing the other is how a tag ends up half shut. Kept here too because this is where someone working on NFC looks.
Diagnostics

Which NFC IC is fitted is detected at runtime, so the address and register layout below come from the tag, not from an assumption here. Recover clocks a jammed bus free and scans for the chip again – the device address of some NFC ICs lives in their own writable EEPROM, so a chip can legitimately move.

                Tag log (live)
                    closed
                
                

                    

                        
                        
                        
                    

                    
                    
Everything the tag would have printed on its UART.
                        Opening this box tells the tag to send it as it is printed; closing
                        it tells the tag to stop. Nothing is polled in between, so a quiet
                        tag costs no traffic at all, and what it sends is dropped from its
                        buffer on the way out, so nothing arrives twice. The tag switches
                        it off by itself whenever the link drops, which is why it is always
                        off after a reconnect until this box is opened again.
